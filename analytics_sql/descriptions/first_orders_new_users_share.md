# First Orders and New User Orders Share

**Задача:** для каждого дня определить долю новых пользователей и долю заказов от новичков от общего числа заказов.

**SQL-файл:** [first_orders_new_users_share.sql](../sql/first_orders_new_users_share.sql)

---

## Предположения о данных

- user_actions содержит записи о действиях пользователей, включая создание и отмену заказов
- Поле time хранит timestamp действия
- Один пользователь может совершать несколько заказов
- Регистрацией считается первое действие пользователя в системе, независимо от типа
- Отменённые заказы исключаются из расчётов заказов, но не влияют на определение даты первого появления пользователя

---

## Логика решения

### 1. not_canceled_orders
Извлекаются все заказы из user_actions, для которых не существует записи с действием отмены. Для каждого заказа фиксируется дата, идентификатор пользователя и время создания.

### 2. calculate_first_orders
Для каждого пользователя из неотменённых заказов находится время первого заказа. Затем по каждой дате подсчитывается, сколько пользователей впервые появилось в системе. Результат — количество новых пользователей по дням.

### 3. order_summary
На основе неотменённых заказов формируются две метрики по каждому дню:

- общее количество заказов;
- количество заказов, совершённых в день первого появления пользователя в системе.

Дата первого появления определяется по всем действиям пользователя, включая отмены, так как любая активность считается регистрацией.

### 4. Финальный запрос
Два потока данных склеиваются через FULL JOIN по дате. Для дней, где присутствует только одна из метрик, отсутствующие значения заменяются через COALESCE.

Рассчитываются две доли:
- отношение количества новых пользователей к общему числу заказов;
- отношение заказов от новичков к общему числу заказов.

Результат округляется до двух знаков после запятой.

---

## Использованные методы

| Категория | Метод | Зачем |
|:---|:---|:---|
| Фильтрация | NOT EXISTS | Исключение отменённых заказов из расчёта заказов |
| Агрегация | MIN по времени | Определение момента первого появления пользователя |
| Агрегация | COUNT с группировкой | Подсчёт новых пользователей по дням |
| Агрегация | Агрегатная фильтрация FILTER | Выделение заказов, совершённых в день регистрации пользователя |
| Склейка | FULL JOIN | Сохранение всех дат из обоих потоков |
| Защита | COALESCE | Замена NULL на исходное значение после FULL JOIN |
| Защита | NULLIF с нулём | Предотвращение деления на ноль в дни без заказов |
| Форматирование | ROUND | Округление долей до двух знаков |
| Приведение типов | CAST к DECIMAL | Корректное деление с дробной частью, переносимо между диалектами SQL |

## Защита от краевых случаев

| Ситуация | Решение |
|:---|:---|
| День с новыми пользователями, но без заказов | FULL JOIN сохраняет строку, COALESCE заменяет отсутствующие заказы на NULL, NULLIF блокирует деление |
| День с заказами, но без новых пользователей | Симметрично: FULL JOIN сохраняет дату, COALESCE заменяет отсутствующих новичков на NULL |
| День без заказов | NULLIF в знаменателе возвращает NULL вместо ошибки деления на ноль |
| Пользователь с отменённым первым заказом | Дата регистрации определяется по всем действиям, включая отмены, так что пользователь не потеряется |

---

## Проверка корректности

Для валидации можно проверить, что количество new_users_orders не превышает общее число заказов за день. Также можно сравнить сумму first_orders за все даты с общим количеством уникальных пользователей в not_canceled_orders — эти значения должны совпадать.

---

## Ограничения

- first_orders отражает количество новых пользователей, а не заказов. Если пользователь сделал несколько заказов в день регистрации, first_orders увеличится на единицу, а new_users_orders — на число заказов.
- Дата регистрации определяется по всем действиям в user_actions, включая отмены. Если бизнес-логика требует считать регистрацией только первый неотменённый заказ, потребуется связка с not_canceled_orders.
- Запрос не гарантирует непрерывность календаря. Дни без заказов и без новых пользователей отсутствуют в выводе.

## Применение

Отчёт позволяет оценивать приток новой аудитории и её вклад в общий объём заказов. Снижение first_orders_share при стабильном числе заказов сигнализирует о том, что рост обеспечивается существующей базой, а не новыми пользователями. Рост new_users_orders_share при высоком first_orders_share указывает на активное вовлечение новичков с первого дня.
