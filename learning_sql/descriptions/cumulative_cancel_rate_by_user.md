# Cumulative Cancel Rate by User

**Задача:** для каждого пользователя посчитать накопительный процент отменённых заказов в хронологическом порядке.

**SQL-файл:** [`cumulative_cancel_rate_by_user.sql`](../sql/cumulative_cancel_rate_by_user.sql)

## Логика решения

1. **metrics**  
   Для каждого пользователя считаем две метрики:
   - `created_orders` — количество созданных заказов нарастающим итогом;
   - `canceled_orders` — количество отменённых заказов нарастающим итогом.  
   Расчёт ведётся отдельно по каждому пользователю в порядке времени.

2. **Финальный запрос**  
   Делим число отменённых заказов на число созданных.  
   Получаем накопительный `cancel_rate` на каждый момент времени.

## Использованные методы

- **CTE (`WITH`)** — вынесение расчёта метрик в отдельный слой.
- **Оконные функции `COUNT ... OVER`** — накопительный подсчёт по пользователю.
- **`FILTER`** — отдельный подсчёт созданных и отменённых заказов.
- **`PARTITION BY` + `ORDER BY`** — расчёт внутри каждого пользователя во времени.
- **`CAST ... AS DECIMAL`** — приведение к дробному типу перед делением.
- **`NULLIF`** — защита от деления на ноль.
- **`COALESCE`** — замена возможного `NULL` на `0`.
- **`ROUND`** — округление до двух знаков.

## Что показывает результат

| Колонка | Описание |
|:---|:---|
| `user_id` | Идентификатор пользователя |
| `order_id` | Идентификатор заказа |
| `action` | Действие пользователя |
| `time` | Время действия |
| `created_orders` | Накопленное количество созданных заказов |
| `canceled_orders` | Накопленное количество отменённых заказов |
| `cancel_rate` | Доля отменённых заказов на текущий момент |

## Вывод

Запрос позволяет отслеживать, как менялось поведение пользователя во времени. Это полезно для выявления пользователей, склонных к отказам, и анализа жизненного цикла клиента.
