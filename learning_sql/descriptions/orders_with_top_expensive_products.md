# Orders Containing Top Expensive Products (Non-Canceled Only)

**Задача:** найти все **неотменённые** заказы, в состав которых входит хотя бы один товар из топ-5 самых дорогих товаров.

**SQL-файл:** [`orders_with_top_expensive_products.sql`](../sql/orders_with_top_expensive_products.sql)  

**Оптимизированный SQL-файл:** [`orders_with_top_expensive_products_optimized.sql`](../sql/orders_with_top_expensive_products_optimized.sql)

---

## Основной запрос

Подробная версия решения с промежуточными шагами.

### Логика решения

1. **all_canceled_orders**  
   Находим все отменённые заказы.

2. **all_not_canceled_orders**  
   Оставляем только заказы, которых нет в списке отменённых.

3. **top_expensive_products**  
   Выбираем топ-5 самых дорогих товаров.

4. **expanded_orders**  
   Разворачиваем массивы товаров в строки и оставляем только неотменённые заказы.

5. **orders_with_expensive_products**  
   Оставляем заказы, в которых есть хотя бы один товар из топ-5 дорогих.

6. **Финальный запрос**  
   Выводим исходные заказы с их полным составом товаров.

### Использованные методы

- **CTE (`WITH`)** - декомпозиция задачи на логические этапы.
- **`EXISTS` / `NOT EXISTS`** - фильтрация отменённых и дорогих заказов.
- **`UNNEST`** - разворачивание массива товаров в строки.
- **`ORDER BY ... DESC` + `LIMIT`** - выбор самых дорогих товаров.
- **Связь через `EXISTS`** - возврат исходных заказов без дублирования строк.

### Что показывает результат

| Колонка | Описание |
|:---|:---|
| `order_id` | Идентификатор заказа |
| `product_ids` | Массив идентификаторов товаров в заказе |

## Оптимизированный запрос

Более компактная и быстрая версия, решающая ту же задачу.

### Отличия и преимущества

- Вместо `UNNEST` используется `ANY(o.product_ids)` - проверка массива без разворачивания в строки.
- Нет промежуточных CTE `expanded_orders` и `orders_with_expensive_products`.
- Меньше операций с памятью и быстрее на больших объёмах данных.
- Прирост в скорости зависит от данных, но в среднем версия с `ANY` работает заметно эффективнее за счёт отсутствия лишнего разворачивания строк.

### Использованные методы

- **CTE (`WITH`)** - изоляция списков отменённых заказов и дорогих товаров.
- **`EXISTS`** - проверка условий на уровне строки без дополнительных объединений.
- **`ANY`** - эффективная проверка вхождения товара из массива в список топ-5.
- **`ORDER BY ... DESC` + `LIMIT`** - выбор самых дорогих товаров.

### Что показывает результат

| Колонка | Описание |
|:---|:---|
| `order_id` | Идентификатор заказа |
| `product_ids` | Массив идентификаторов товаров в заказе |

## Вывод

Запрос позволяет находить успешные заказы с премиальными товарами. Это полезно для анализа покупательского поведения, сегментации клиентов и планирования маркетинговых акций, связанных с дорогими позициями.
