# Order Revenue Share by Day

**SQL-файл:** [`order_revenue_share_by_day.sql`](https://github.com/pasqalex/practiceSQL/blob/main/sql/order_revenue_share_by_day.sql)

**Задача:** для каждого неотменённого заказа посчитать его стоимость, дневную выручку и долю заказа в этой выручке.

## Логика решения

Запрос разбит на несколько CTE, каждый из которых отвечает за свою часть логики.

### 1. canceled_orders

Находим все заказы, которые были отменены.

Этот список понадобится, чтобы исключить отменённые заказы из дальнейших расчётов.

### 2. not_canceled_orders

Оставляем только те заказы, которых нет в списке отменённых.

Для этого используется `NOT EXISTS`.

Такой подход надёжно отсеивает отменённые заказы и не зависит от количества действий по одному заказу.

### 3. warp

Основной расчётный слой. Здесь происходит несколько вещей:

- `UNNEST(product_ids)` разворачивает массив товаров в строки;
- `JOIN products` подтягивает цену каждого товара;
- `SUM(price)` считает стоимость заказа;
- `SUM(SUM(price)) OVER(PARTITION BY order_date)` считает выручку за день.

Оконная функция здесь используется, чтобы не создавать отдельный CTE с дневной выручкой.  
Она берёт уже посчитанную стоимость заказа и суммирует её по всем заказам одной даты.

Такой приём позволяет посчитать дневную выручку в том же слое, где считается стоимость заказа.

### 4. Финальный запрос

На последнем шаге:

- берём стоимость заказа;
- делим её на дневную выручку;
- умножаем на 100;
- округляем до трёх знаков.

Получаем долю заказа в дневной выручке.

## Использованные методы

- **CTE (`WITH`)** — разбиение задачи на логические слои.
- **`NOT EXISTS`** — исключение отменённых заказов.
- **`UNNEST`** — разворачивание массива товаров в строки.
- **`JOIN`** — подтягивание цен товаров.
- **`SUM` + `GROUP BY`** — расчёт стоимости заказа.
- **`SUM(SUM(...)) OVER(PARTITION BY ...)`** — оконная агрегация для дневной выручки.
- **`CAST` + `DECIMAL`** — корректное деление с дробной частью.
- **`NULLIF`** — защита от деления на ноль.
- **`ROUND`** — округление результата.

## Что показывает результат

| Колонка | Описание |
|:---|:---|
| `order_id` | Идентификатор заказа |
| `creation_time` | Время создания заказа |
| `order_price` | Стоимость заказа |
| `daily_revenue` | Выручка за день |
| `percentage_of_daily_revenue` | Доля заказа в дневной выручке, % |

## Вывод

Запрос позволяет понять, насколько значим каждый заказ в общей выручке дня. Это полезно для выявления крупных клиентов, анализа аномалий и планирования маркетинговых активностей.
