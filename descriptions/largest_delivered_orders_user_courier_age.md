# Users and Couriers in Largest Delivered Orders

**Задача:** найти доставленные заказы с максимальным количеством товаров и для каждого из них вывести пользователя, курьера и их возраст.

**SQL-файл:** [`largest_delivered_orders_user_courier_age.sql`](../sql/largest_delivered_orders_user_courier_age.sql)

## Логика решения

1. **expand_orders**  
   Для каждого заказа считаем количество товаров через `array_length`.

2. **max_of_orders**  
   Находим максимальное количество товаров среди всех заказов.

3. **order_ids_with_max_count_of_products**  
   Отбираем только те заказы, где количество товаров равно максимальному.

4. **couriers_ids**  
   Оставляем только доставленные заказы и подтягиваем к ним курьера и пользователя.

5. **starting_point_for_age**  
   Определяем единую дату отсчёта - максимальную дату из `user_actions`.

6. **Финальный запрос**  
   Для каждой связки «курьер-пользователь-заказ» считаем возраст пользователя и курьера на максимальную дату.

## Использованные методы

- **CTE (`WITH`)** - пошаговая декомпозиция задачи.
- **`ARRAY_LENGTH`** - определение количества товаров в заказе.
- **`MAX()`** - поиск максимального размера заказа.
- **`EXISTS`** - динамическое сравнение с максимальным значением.
- **`JOIN` + `USING`** - связывание заказов, курьеров и пользователей.
- **`CROSS JOIN`** - подстановка единой даты расчёта ко всем строкам.
- **`AGE` + `EXTRACT`** - вычисление возраста в годах.
- **`CAST`** - приведение возраста к целому числу.

## Почему `EXISTS`, а не подзапрос с равенством

Вместо прямого сравнения с максимальным значением используется `EXISTS`.  
Это позволяет базе корректно проверять каждую строку `expand_orders` и не зависеть от особенностей выполнения подзапроса.

## Что показывает результат

| Колонка | Описание |
|:---|:---|
| `courier_id` | Идентификатор курьера |
| `user_id` | Идентификатор пользователя |
| `order_id` | Идентификатор заказа |
| `user_age` | Возраст пользователя |
| `courier_age` | Возраст курьера |

## Вывод

Запрос позволяет проанализировать самые крупные доставленные заказы и участников этих заказов. Это полезно для изучения поведения пользователей и загруженности курьеров в пиковых ситуациях.
