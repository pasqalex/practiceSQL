# First vs Repeat Orders by Day

**SQL-файл:** [`first_vs_repeat_orders_by_day.sql`](../sql/first_vs_repeat_orders_by_day.sql)

**Задача:** посчитать, сколько каждый день было первых и повторных заказов среди неотменённых.

## Логика решения

1. **canceled_orders**  
   Находим все отменённые заказы.

2. **all_not_canceled_orders**  
   Оставляем только неотменённые заказы.  
   Сохраняем `user_id`, `order_id` и `time`.

3. **find_the_meaning_of_life**  
   Для каждого заказа определяем его тип:
   - `Первый` — если это первый заказ пользователя по времени;
   - `Повторный` — если пользователь уже делал заказ раньше.  
   Для этого используется оконная функция `RANK()` с `PARTITION BY user_id`.

4. **Финальный запрос**  
   Группируем заказы по дате и типу.  
   Считаем количество заказов в каждой группе.

## Использованные методы

- **CTE (`WITH`)** — декомпозиция задачи на логические слои.
- **`NOT EXISTS`** — исключение отменённых заказов.
- **Оконная функция `RANK()`** — определение первого заказа пользователя.
- **`PARTITION BY`** — расчёт внутри каждого пользователя.
- **`CASE`** — присвоение заказу типа `Первый` или `Повторный`.
- **`COUNT` + `GROUP BY`** — подсчёт количества заказов по датам и типам.

## Почему `RANK()`, а не `ROW_NUMBER()`

`RANK()` выбран для того, чтобы заказы, сделанные пользователем в одно и то же время, считались одинаково первыми.

Пример: если у пользователя есть два заказа с одинаковым временем, оба получат `RANK = 1` и будут отнесены к типу `Первый`.

`ROW_NUMBER()` в такой ситуации присвоил бы одной строке `1`, другой — `2`.  
Тогда один из одновременных заказов стал бы «Повторным», что исказило бы картину.

## Что показывает результат

| Колонка | Описание |
|:---|:---|
| `date` | Дата заказа |
| `order_type` | Тип заказа: `Первый` или `Повторный` |
| `orders_count` | Количество заказов этого типа в дату |

## Вывод

Запрос позволяет увидеть динамику привлечения новых пользователей и активности возвращающихся. Это полезно для оценки маркетинговых кампаний, удержания клиентов и анализа поведения пользователей.

# First Purchases by Day (Alternative without Window Functions)

**SQL-файл:** [`first_purchases_by_day.sql`](../sql/first_purchases_by_day.sql)

**Задача:** посчитать количество первых покупок пользователей по дням.

Это альтернативное решение той же задачи, написанное до изучения оконных функций и `JOIN`.

## Логика решения

1. **all_canceled_orders**  
   Находим все отменённые заказы.

2. **all_not_canceled_orders**  
   Оставляем только неотменённые заказы.  
   Для каждого пользователя сохраняем дату заказа.

3. **find_minimal_date_of_purchase**  
   Для каждого пользователя находим минимальную дату заказа — это и есть первая покупка.

4. **Финальный запрос**  
   Считаем количество пользователей, совершивших первую покупку в каждую дату.

## Использованные методы

- **CTE (`WITH`)** — декомпозиция задачи.
- **`NOT EXISTS`** — исключение отменённых заказов.
- **`CAST(time AS DATE)`** — приведение времени к дате.
- **`MIN` + `GROUP BY`** — поиск первой даты покупки.
- **`COUNT` + `GROUP BY`** — подсчёт количества первых покупок по дням.

## Сравнение подходов

Первый запрос использует оконную функцию `RANK()` и позволяет сразу разделить заказы на первые и повторные.

Второй запрос решает задачу без оконок: сначала находит минимальную дату, затем агрегирует.

Оба варианта дают корректный результат. Второй — проще для понимания новичкам, первый — гибче и лучше масштабируется на более сложные задачи.
