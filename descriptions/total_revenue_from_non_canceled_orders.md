# Sales Sum of Non-Canceled Orders

**Задача:** посчитать суммарную стоимость всех неотменённых заказов.

**SQL-файл:** [`total_revenue_from_non_canceled_orders.sql`](../sql/total_revenue_from_non_canceled_orders.sql)

## Логика решения

1. **all_not_canceled_orders**  
   Определяем все `order_id`, которые не были отменены.  
   Для этого проверяем, что по каждому заказу в `user_actions` нет записи с действием `cancel_order`.

2. **price_of_not_canceled_orders**  
   Для каждого неотменённого заказа:
   - разворачиваем массив товаров (`product_ids`) в отдельные строки;
   - связываем товары с таблицей `products`;
   - суммируем цены товаров внутри одного заказа.

3. **Финальный запрос**  
   Суммируем стоимости всех неотменённых заказов.

## Использованные методы

- **CTE (`WITH`)** - декомпозиция задачи на логические этапы.
- **`NOT EXISTS`** - исключение отменённых заказов через связанный подзапрос.
- **`UNNEST`** - разворачивание массива товаров в строки.
- **`LEFT JOIN`** - подтягивание цены товара из таблицы `products`.
- **`SUM() + GROUP BY`** - расчёт стоимости каждого заказа и общей суммы.

## Особенности запроса

- **Гибкость использования CTE.**  
  CTE `price_of_not_canceled_orders` можно использовать отдельно от финального запроса.  
  Если убрать внешнюю агрегацию, мы получим стоимость каждого неотменённого заказа по отдельности.

- **Обработка `NULL` в ценах.**  
  Если товар отсутствует в таблице `products`, его цена будет `NULL`.  
  Функция `SUM` игнорирует `NULL`, поэтому итоговая сумма не искажается.

- **Отсутствие дублей.**  
  `UNNEST` создаёт несколько строк для одного заказа, но `GROUP BY order_id` собирает их обратно в одну строку с суммой.

- **Читаемость через вложенный подзапрос.**  
  В `price_of_not_canceled_orders` используется подзапрос `expanded_orders` для разворачивания массивов. Это позволяет отделить логику работы с массивами от логики суммирования цен.

## Что показывает результат

| Колонка | Описание |
|:---|:---|
| `sum` | Общая сумма всех неотменённых заказов |

## Вывод

Запрос позволяет оценить выручку, которая получена с успешных заказов. Это полезно для анализа реальных продаж, исключая возвраты и отмены.
